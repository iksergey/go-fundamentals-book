# Вложенные условия и best practices

## Краткое описание

**Вложенные условия** — размещение одного блока if-else **внутри** другого блока if-else. Вложенность может быть бесконечно большой, но **глубокая вложенность** (3+ уровня) **снижает читаемость** кода. В профессиональной разработке вложенность глубже 2 уровней считается **плохой практикой** и требует рефакторинга. Используйте **guard clauses** (ранние проверки), **else if** или **комбинирование условий** с && для упрощения логики.

***

## Вложенные if-else

### Синтаксис

    if внешнее_условие {
        // Код выполняется если внешнее_условие == true
        
        if внутреннее_условие {
            // Выполняется если ОБА условия true
        } else {
            // Выполняется если внешнее true, внутреннее false
        }
        
    } else {
        // Выполняется если внешнее_условие == false
        // Внутреннее условие НЕ ПРОВЕРЯЕТСЯ!
    }

### Логика работы

1. **Проверяется внешнее условие**
2. **Если false** → блок else внешнего условия, **внутреннее НЕ проверяется**
3. **Если true** → переход внутрь блока, проверка внутреннего условия
4. **Вложенное условие** работает **только** если внешнее выполнено

***

## Пример 1: Проверка возраста и прав

### Задача

Проверить, может ли пользователь водить машину:
1. Должен быть совершеннолетним (18+)
2. Должны быть водительские права

### Код

    userAge := 25
    hasLicense := true

    fmt.Printf("userAge = %d\n", userAge)
    fmt.Printf("hasLicense = %t\n", hasLicense)

    if userAge >= 18 {
        fmt.Println("Возраст достаточен")
        
        if hasLicense {
            fmt.Println("Есть права")
            fmt.Println("✓ Может водить машину")
        } else {
            fmt.Println("Нет прав")
            fmt.Println("✗ Не может водить машину")
        }
    } else {
        fmt.Println("Возраст недостаточен")
        fmt.Println("✗ Не может водить машину")
    }

### Пошаговое выполнение

**Сценарий 1: userAge = 25, hasLicense = true**

1. Проверка: 25 >= 18 → **true** ✅
2. Выполняется: "Возраст достаточен"
3. **Внутренняя проверка:** hasLicense → **true** ✅
4. Выполняется: "Есть права", "✓ Может водить машину"

**Сценарий 2: userAge = 25, hasLicense = false**

1. Проверка: 25 >= 18 → **true** ✅
2. Выполняется: "Возраст достаточен"
3. **Внутренняя проверка:** hasLicense → **false** ❌
4. Выполняется блок **else**: "Нет прав", "✗ Не может водить машину"

**Сценарий 3: userAge = 15, hasLicense = true**

1. Проверка: 15 >= 18 → **false** ❌
2. Выполняется блок **else**: "Возраст недостаточен", "✗ Не может водить машину"
3. **Внутреннее условие НЕ ПРОВЕРЯЕТСЯ!**

### Важно

Если **внешнее условие false**, то **весь внутренний блок пропускается** — внутреннее условие даже не вычисляется.

## Пример 2: Система скидок

### Задача

Магазин предоставляет скидки:
- Покупка >= 100 денег → есть скидка
  - Член клуба → **15% скидка**
  - Обычный покупатель → **10% скидка**
- Покупка < 100 денег → **нет скидки**

### Код

    purchaseAmount := 150.0
    isMember := true

    fmt.Printf("purchaseAmount = %.2f\n", purchaseAmount)
    fmt.Printf("isMember = %t\n", isMember)

    if purchaseAmount >= 100 {
        fmt.Println("Покупка больше 100 денег")
        
        if isMember {
            discount := purchaseAmount * 0.15  // 15%
            finalPrice := purchaseAmount - discount
            fmt.Printf("Скидка для члена: 15%% = $%.2f\n", discount)
            fmt.Printf("Итоговая цена: $%.2f\n", finalPrice)
        } else {
            discount := purchaseAmount * 0.10  // 10%
            finalPrice := purchaseAmount - discount
            fmt.Printf("Скидка: 10%% = $%.2f\n", discount)
            fmt.Printf("Итоговая цена: $%.2f\n", finalPrice)
        }
    } else {
        fmt.Println("Покупка меньше 100 денег")
        fmt.Printf("Скидок нет, цена: $%.2f\n", purchaseAmount)
    }

### Вывод (purchaseAmount = 150, isMember = true)

    purchaseAmount = 150.00
    isMember = true
    Покупка больше 100 денег
    Скидка для члена: 15% = $22.50
    Итоговая цена: $127.50

## Проблема глубокой вложенности

### ❌ Плохо: глубокая вложенность (3+ уровня)

    userRole := "admin"
    isActive := true
    hasPermission := true

    if userRole == "admin" {
        fmt.Println("Уровень вложенности 1")
        
        if isActive {
            fmt.Println("Уровень вложенности 2")
            
            if hasPermission {
                fmt.Println("Уровень вложенности 3")
                fmt.Println("Это становится трудно читать")
            }
        }
    }

### Почему это плохо

1. **Сложно читать** — глаза "прыгают" между уровнями
2. **Сложно отлаживать** — непонятно, где ошибка
3. **Сложно тестировать** — много комбинаций путей
4. **Неочевидная логика** — что проверяется на каждом уровне

### Правило

**Вложенность > 2 уровней** — повод **переписать** код!

В production-коде вы увидите пометку:

    // TODO: refactor this nested hell

***

## Best Practice 1: Guard Clauses (ранние проверки)

### ✅ Хорошо: упрощённая логика

    if userRole != "admin" {
        fmt.Println("Not admin, stop here")
    } else if !isActive {
        fmt.Println("Not active, stop here")
    } else if !hasPermission {
        fmt.Println("No permission, stop here")
    } else {
        fmt.Println("Все проверки пройдены")
        fmt.Println("Одинаковый уровень вложенности")
        fmt.Println("Код легче читать")
    }

### Преимущества

- **Плоская структура** — все условия на одном уровне
- **Ранний выход** — сразу видно, где остановка
- **Читаемость** — логика понятна с первого взгляда
- **Меньше отступов** — код не "уезжает" вправо

***

## Best Practice 2: Комбинирование условий

### ❌ Плохо: вложенность

    if userAge >= 18 {
        if hasLicense {
            fmt.Println("Может водить")
        }
    }

### ✅ Хорошо: одно условие с &&

    if userAge >= 18 && hasLicense {
        fmt.Println("Может водить")
    }

### Когда использовать

Если обе проверки **независимы** и нужны **одновременно**, используйте **&&**.

***

## Best Practice 3: Переменные для сложных условий

### ✅ Самодокументируемый код

    canDrive := (userAge >= 18) && hasLicense

    if canDrive {
        fmt.Println("Может водить")
    }

### Преимущества

- **Именованное условие** — понятно, что проверяется
- **Переиспользование** — можно использовать несколько раз
- **Тестируемость** — легко проверить отдельно

***

## Практический пример: вход в систему

### ❌ Вариант 1: Множественная вложенность (плохо)

    username := "john"
    password := "pass123"
    correctUsername := "john"
    correctPassword := "pass123"
    accountLocked := false

    if !accountLocked {
        if username == correctUsername {
            if password == correctPassword {
                fmt.Println("✓ Вход успешен")
            } else {
                fmt.Println("✗ Неправильный пароль")
            }
        } else {
            fmt.Println("✗ Неправильное имя пользователя")
        }
    } else {
        fmt.Println("✗ Аккаунт заблокирован")
    }

**Проблема:** 3 уровня вложенности, сложно читать.

### ✅ Вариант 2: Guard clauses (хорошо)

    if accountLocked {
        fmt.Println("✗ Аккаунт заблокирован")
    } else if username != correctUsername {
        fmt.Println("✗ Неправильное имя пользователя")
    } else if password != correctPassword {
        fmt.Println("✗ Неправильный пароль")
    } else {
        fmt.Println("✓ Вход успешен")
    }

**Преимущества:** 
- Плоская структура
- Ранние проверки
- Легко добавить новые условия
- Читаемость на 100%

***

## Когда использовать каждый подход

### Используйте вложенность

- **Максимум 2 уровня**
- Когда внутренняя логика **зависит** от внешней
- Когда разные блоки имеют **разный контекст**

### Используйте guard clauses

- Для **валидации** входных данных
- Для **проверки прав** доступа
- Когда нужно **остановить** выполнение
- Когда условия **независимы**

### Используйте комбинирование (&&)

- Когда оба условия нужны **одновременно**
- Когда условия **простые** и **понятные**
- Когда результат **бинарный** (да/нет)

***

## Рекомендации для чистого кода

### 1. Избегайте глубокой вложенности

    // ❌ Плохо: 4+ уровня
    if a {
        if b {
            if c {
                if d {
                    // ...
                }
            }
        }
    }

    // ✅ Хорошо: плоская структура
    if !a {
        return
    }
    if !b {
        return
    }
    if !c {
        return
    }
    if !d {
        return
    }
    // ...

### 2. Используйте раннюю валидацию

    // ✅ Сначала проверяем ошибки
    if !hasItems {
        fmt.Println("Ошибка: нет товаров")
        return
    }
    if orderTotal <= 0 {
        fmt.Println("Ошибка: некорректная сумма")
        return
    }
    
    // Основная логика
    fmt.Println("✓ Заказ обработан")

### 3. Разбивайте сложную логику

    // ❌ Плохо: всё в одном месте
    if userRole == "admin" && isActive && hasPermission && !accountLocked {
        // ...
    }

    // ✅ Хорошо: поэтапная проверка
    if userRole != "admin" {
        return
    }
    if !isActive {
        return
    }
    if !hasPermission {
        return
    }
    if accountLocked {
        return
    }
    // ...

### 4. Именуйте сложные условия

    // ✅ Переменная для читаемости
    isEligibleForDiscount := (purchaseAmount >= 100) && isMember
    
    if isEligibleForDiscount {
        // ...
    }

### 5. Комментируйте неочевидную логику

    // Проверяем права администратора для удаления
    if userRole == "admin" || (isOwner && createdAt.Before(time.Now().Add(-24*time.Hour))) {
        // ...
    }

## Ключевые моменты

1. **Вложенность** — один if внутри другого
2. **Глубокая вложенность** (3+) — **плохая практика**
3. **Guard clauses** — ранние проверки и выход
4. **else if** — альтернатива вложенности
5. **Комбинирование &&** — вместо вложенных if
6. **Именованные условия** — для сложной логики
7. **Читаемость** — приоритет над краткостью
8. **Рефакторинг** — если вложенность > 2 уровней
9. **Плоская структура** — легче читать и отлаживать
10. **Ранняя валидация** — сначала проверки, потом логика

***

## Что запомнить

- **Вложенность возможна**, но **опасна**
- **Максимум 2 уровня** — дальше рефакторинг
- **Guard clauses** — проверяй и выходи рано
- **else if** вместо вложенных if
- **&&** вместо if внутри if
- **Именуй** сложные условия
- **Читаемость** важнее краткости
- **Комбинируй** подходы разумно
- **Тестируй** все пути выполнения
- **Рефактори** код с глубокой вложенностью

***

## Быстрая проверка: нужен ли рефакторинг?

**Задайте себе вопросы:**

1. Больше 2 уровней вложенности? → **Рефакторинг**
2. Сложно понять логику с первого взгляда? → **Рефакторинг**
3. Много отступов (код "уехал" вправо)? → **Рефакторинг**
4. Трудно тестировать все пути? → **Рефакторинг**
5. Есть дублирование условий? → **Рефакторинг**

***

**Итог:** Вложенные условия допустимы до 2 уровней. Глубокая вложенность снижает читаемость — используйте guard clauses, else if или комбинируйте условия с &&. Читаемость кода — главный приоритет. Если видите 3+ уровня вложенности — перепишите код.
