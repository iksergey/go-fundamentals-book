# Оператор switch: альтернатива каскадам if-else

## Краткое описание

**Оператор switch** — конструкция для проверки **множественных значений** переменной или условий, более компактная и читаемая альтернатива каскадам `if-else if`. Синтаксис: `switch выражение { case значение: ... }`. Ключевые особенности Go: **автоматический break** (не нужно писать явно), возможность **множественных значений** в одном case через запятую, поддержка **switch без выражения** (замена if-else), **fallthrough** для явного проваливания в следующий case, **инициализация переменных** в switch, **type switch** для проверки типов. Оператор switch делает код **чище, короче и читаемее**, особенно при проверке 3+ условий.

***

## Базовый синтаксис switch

### Общая форма

```go
switch выражение {
case значение1:
    // Код для значения1
case значение2:
    // Код для значения2
case значение3:
    // Код для значения3
default:
    // Код если ни один case не подошёл (опционально)
}
```

### Структура

1. **Ключевое слово** `switch`
2. **Выражение** — переменная или выражение для проверки
3. **case значение:** — каждый возможный вариант
4. **default:** — блок по умолчанию (опционален)
5. **Автоматический выход** — break не нужен

***

## Пример 1: Дни недели

### Задача

Вывести название дня недели по номеру (1-5).

### Код

```go
day := 3
fmt.Printf("day = %d\n", day)

switch day {
case 1:
    fmt.Println("Понедельник")
case 2:
    fmt.Println("Вторник")
case 3:
    fmt.Println("Среда")  // выполнится
case 4:
    fmt.Println("Четверг")
case 5:
    fmt.Println("Пятница")
}
```

### Пошаговое выполнение (day = 3)

**Шаг 1:** Вход в `switch day`

**Шаг 2:** Проверка `case 1:` → 3 ≠ 1 → пропуск

**Шаг 3:** Проверка `case 2:` → 3 ≠ 2 → пропуск

**Шаг 4:** Проверка `case 3:` → 3 == 3 ✅ → выполнение

**Шаг 5:** Вывод "Среда"

**Шаг 6:** **Автоматический выход** из switch (break не нужен!)

**Результат:**
```
day = 3
Среда
```

### Важно

После выполнения case **автоматически происходит выход** из switch. Не нужно писать `break`.

***

## Ключевое отличие от Java/C#/C++

### В Java/C#/C++ (требуется break)

```java
// Java
switch (day) {
    case 1:
        System.out.println("Понедельник");
        break;  // ОБЯЗАТЕЛЬНО!
    case 2:
        System.out.println("Вторник");
        break;  // ОБЯЗАТЕЛЬНО!
    case 3:
        System.out.println("Среда");
        break;  // ОБЯЗАТЕЛЬНО!
}
```

**Без break:** выполнение "проваливается" в следующий case (fall-through).

### В Go (break автоматический)

```go
// Go
switch day {
case 1:
    fmt.Println("Понедельник")
    // break НЕ НУЖЕН - автоматический выход
case 2:
    fmt.Println("Вторник")
    // break НЕ НУЖЕН
case 3:
    fmt.Println("Среда")
    // break НЕ НУЖЕН
}
```

**По умолчанию:** автоматический выход после выполнения case.

### Сравнительная таблица

| Характеристика | Java/C#/C++ | Go |
|---|---|---|
| **break после case** | ✅ Обязательно | ❌ Не нужен |
| **Автоматический выход** | ❌ Нет | ✅ Да |
| **Fall-through** | По умолчанию | Явно через `fallthrough` |
| **Безопасность** | Ошибка забыть break | Безопасно по умолчанию |

## Switch с выражением

### Синтаксис

```go
switch переменная {
case значение1:
    // код
case значение2:
    // код
}
```

### Пример: выборочные значения

```go
number := 10
fmt.Printf("number = %d\n", number)

switch number {
case 5:
    fmt.Println("Пять")
case 10:
    fmt.Println("Десять")  // выполнится
case 15:
    fmt.Println("Пятнадцать")
}
```

**Результат:**
```
number = 10
Десять
```

### Важно

**Не обязательно проверять все значения по порядку.** Можно проверять только нужные: 5, 10, 15 (без 6, 7, 8, 9...).

## Switch без выражения (замена if-else if)

### Синтаксис

```go
switch {
case условие1:
    // код
case условие2:
    // код
default:
    // код по умолчанию
}
```

### Пример: диапазоны возрастов

```go
age := 52
fmt.Printf("age = %d\n", age)

switch {
case age < 13:
    fmt.Println("Ребёнок")
case age < 20:
    fmt.Println("Подросток")
case age < 60:
    fmt.Println("Взрослый")  // выполнится
default:
    fmt.Println("Пожилой")
}
```

**Пошаговое выполнение (age = 52):**

**Шаг 1:** Вход в `switch` (без выражения)

**Шаг 2:** Проверка `age < 13` → 52 < 13 → **false**

**Шаг 3:** Проверка `age < 20` → 52 < 20 → **false**

**Шаг 4:** Проверка `age < 60` → 52 < 60 → **true** ✅

**Шаг 5:** Вывод "Взрослый"

**Шаг 6:** Автоматический выход

**Результат:**
```
age = 52
Взрослый
```

### Сравнение с if-else if

**С помощью if-else if:**

```go
if age < 13 {
    fmt.Println("Ребёнок")
} else if age < 20 {
    fmt.Println("Подросток")
} else if age < 60 {
    fmt.Println("Взрослый")
} else {
    fmt.Println("Пожилой")
}
```

**С помощью switch:**

```go
switch {
case age < 13:
    fmt.Println("Ребёнок")
case age < 20:
    fmt.Println("Подросток")
case age < 60:
    fmt.Println("Взрослый")
default:
    fmt.Println("Пожилой")
}
```

**Преимущества switch:**
- Более структурированный код
- Легче читается
- Явное разделение случаев
- Меньше вложенности

## Множественные значения в case

### Синтаксис

```go
case значение1, значение2, значение3:
    // Выполнится если совпало ЛЮБОЕ значение
```

### Пример: рабочие дни и выходные

```go
dayOfWeek := "Saturday"
fmt.Printf("dayOfWeek = \"%s\"\n", dayOfWeek)

switch dayOfWeek {
case "Monday", "Tuesday", "Wednesday", "Thursday", "Friday":
    fmt.Println("Рабочий день")
case "Saturday", "Sunday":
    fmt.Println("Выходной")  // выполнится
}
```

**Логика:** Проверяется совпадение с **любым** значением в списке через запятую.

**Результат:**
```
dayOfWeek = "Saturday"
Выходной
```

### Важно: чувствительность к регистру

```go
dayOfWeek := "saturday"  // с маленькой буквы

switch dayOfWeek {
case "Monday", "Tuesday", "Wednesday", "Thursday", "Friday":
    fmt.Println("Рабочий день")
case "Saturday", "Sunday":  // "Saturday" с большой буквы
    fmt.Println("Выходной")
}

// Ничего не выполнится!
// "saturday" ≠ "Saturday" (регистр имеет значение)
```

**Вывод:** Строки `"Saturday"` и `"saturday"` — **разные** значения!

## Сравнение switch vs if для множественных значений

### Задача: определить сезон по номеру месяца

**Вариант 1: if-else (громоздко)**

```go
month := 7

if month == 12 || month == 1 || month == 2 {
    fmt.Println("Зима")
} else if month == 3 || month == 4 || month == 5 {
    fmt.Println("Весна")
} else if month == 6 || month == 7 || month == 8 {
    fmt.Println("Лето")
} else if month == 9 || month == 10 || month == 11 {
    fmt.Println("Осень")
} else {
    fmt.Println("Некорректный месяц")
}
```

**Проблемы:**
- Много повторений `month ==`
- Громоздкие условия `|| ||`
- Сложнее читать

**Вариант 2: switch (компактно)**

```go
month := 7

switch month {
case 12, 1, 2:
    fmt.Println("Зима")
case 3, 4, 5:
    fmt.Println("Весна")
case 6, 7, 8:
    fmt.Println("Лето")  // выполнится
case 9, 10, 11:
    fmt.Println("Осень")
default:
    fmt.Println("Некорректный месяц")
}
```

**Преимущества:**
- ✅ Компактно — `case 12, 1, 2` вместо `month == 12 || month == 1 || month == 2`
- ✅ Читаемо — значения сгруппированы
- ✅ Структурно — каждый сезон в своём блоке
- ✅ Меньше символов — короче в ~2 раза

**Результат:**
```
Лето
```

## fallthrough: явное проваливание

### Концепция

В Go **по умолчанию** после выполнения case происходит **автоматический выход**. Если нужно **продолжить** выполнение следующего case, используйте **fallthrough**.

### Синтаксис

```go
switch переменная {
case значение1:
    // код
    fallthrough  // Явно переходим к следующему case
case значение2:
    // Этот код тоже выполнится
    fallthrough
case значение3:
    // И этот тоже
}
```

### Пример: последовательное выполнение

```go
num := 1
fmt.Printf("num = %d\n", num)

switch num {
case 1:
    fmt.Println("Один")
    fallthrough  // Переход к case 2
case 2:
    fmt.Println("Два")  // Выполнится тоже
    fallthrough  // Переход к case 3
case 3:
    fmt.Println("Три")  // И это тоже
case 4:
    fmt.Println("Четыре")  // Это НЕ выполнится (нет fallthrough выше)
}
```

**Пошаговое выполнение (num = 1):**

**Шаг 1:** Проверка `case 1:` → 1 == 1 ✅

**Шаг 2:** Вывод "Один"

**Шаг 3:** Встречен `fallthrough` → **принудительный** переход к `case 2:`

**Шаг 4:** Вывод "Два" (без проверки условия!)

**Шаг 5:** Встречен `fallthrough` → переход к `case 3:`

**Шаг 6:** Вывод "Три" (без проверки условия!)

**Шаг 7:** Нет `fallthrough` → выход из switch

**Результат:**
```
num = 1
Один
Два
Три
```

### Важно

`fallthrough` **безусловно** передаёт управление следующему case **без проверки** его условия!

### Когда использовать

Используйте `fallthrough` **редко**, только когда:
- Нужна последовательная обработка
- Логика требует "накопления" действий
- Явная потребность в проваливании

В большинстве случаев лучше **избегать** fallthrough для читаемости.

## default: блок по умолчанию

### Синтаксис

```go
switch переменная {
case значение1:
    // код
case значение2:
    // код
default:
    // Выполняется если НИ ОДИН case не подошёл
}
```

### Пример: неизвестный цвет

```go
color := "green"
fmt.Printf("color = \"%s\"\n", color)

switch color {
case "red":
    fmt.Println("Красный")
case "blue":
    fmt.Println("Синий")
default:
    fmt.Println("Неизвестный цвет")  // выполнится
}
```

**Логика:**
1. Проверка `case "red":` → "green" ≠ "red" → пропуск
2. Проверка `case "blue":` → "green" ≠ "blue" → пропуск
3. Ни один case не подошёл → выполнение **default**

**Результат:**
```
color = "green"
Неизвестный цвет
```

### Особенности default

- **Опционален** — можно не писать
- **Выполняется** только если ни один case не сработал
- **Можно располагать** в любом месте (но обычно в конце)
- **Аналог** else в if-else

***

## Инициализация переменной в switch

### Синтаксис

```go
switch переменная := выражение; переменная {
case значение1:
    // переменная доступна
case значение2:
    // переменная доступна
}

// переменная НЕ доступна здесь
```

### Пример: время суток по текущему часу

```go
switch hour := time.Now().Hour(); {
case hour < 12:
    fmt.Printf("Сейчас %d часов - утро\n", hour)
case hour < 18:
    fmt.Printf("Сейчас %d часов - день\n", hour)
case hour < 21:
    fmt.Printf("Сейчас %d часов - вечер\n", hour)
default:
    fmt.Printf("Сейчас %d часов - ночь\n", hour)
}

// hour НЕ доступна здесь
```

**Обратите внимание:**
- `hour := time.Now().Hour()` — инициализация переменной
- **Точка с запятой** `;` — разделитель
- `switch ... ; {` — switch без выражения (используются условия в case)
- `hour` доступна во **всех** блоках case и default
- `hour` **недоступна** за пределами switch

### Зачем это нужно

- **Ограничение области видимости** — переменная нужна только в switch
- **Компактность** — объявление и использование в одном месте
- **Безопасность** — переменная не "утекает" наружу

## Type Switch: проверка типов

### Концепция

**Type switch** позволяет проверить **тип** переменной и выполнить соответствующий код.

### Синтаксис

```go
switch переменная := значение.(type) {
case тип1:
    // переменная имеет тип1
case тип2:
    // переменная имеет тип2
default:
    // другой тип
}
```

### Пример: определение типа значения

```go
var value interface{} = 42  // interface{} может хранить любой тип

switch v := value.(type) {
case int:
    fmt.Printf("Это int: %d\n", v)  // выполнится
case string:
    fmt.Printf("Это string: %s\n", v)
case bool:
    fmt.Printf("Это bool: %t\n", v)
default:
    fmt.Printf("Неизвестный тип: %T\n", v)
}
```

**Пошаговое выполнение:**

**Шаг 1:** `value` содержит `42` (тип `int`)

**Шаг 2:** `value.(type)` определяет тип → `int`

**Шаг 3:** Проверка `case int:` → **совпадение** ✅

**Шаг 4:** `v` имеет тип `int` со значением `42`

**Шаг 5:** Вывод "Это int: 42"

**Результат:**
```
Это int: 42
```

### Применение

Type switch полезен когда:
- Работа с `interface{}`
- Обработка разных типов данных
- Универсальные функции
- Десериализация данных

## Когда использовать switch вместо if

### ✅ ИСПОЛЬЗУЙТЕ switch когда:

1. **Проверка 3+ значений одной переменной**
   ```go
   // ✅ Хорошо со switch
   switch statusCode {
   case 200, 201, 204: ...
   case 400, 401, 403: ...
   case 500, 502, 503: ...
   }
   ```

2. **Множественные значения для одного действия**
   ```go
   // ✅ case с несколькими значениями
   switch month {
   case 12, 1, 2:
       fmt.Println("Зима")
   }
   ```

3. **Диапазоны значений (switch без выражения)**
   ```go
   // ✅ Чище чем if-else
   switch {
   case score >= 90: ...
   case score >= 80: ...
   case score >= 70: ...
   }
   ```

4. **Проверка типов (type switch)**
   ```go
   // ✅ Невозможно с if
   switch v := value.(type) {
   case int: ...
   case string: ...
   }
   ```

5. **Константные значения**
   ```go
   // ✅ Явное перечисление
   switch day {
   case "Monday": ...
   case "Tuesday": ...
   }
   ```

### ❌ НЕ используйте switch когда:

1. **Простая бинарная проверка (да/нет)**
   ```go
   // ❌ Избыточно
   switch {
   case x > 0:
       fmt.Println("Положительное")
   default:
       fmt.Println("Не положительное")
   }
   
   // ✅ Лучше if
   if x > 0 {
       fmt.Println("Положительное")
   } else {
       fmt.Println("Не положительное")
   }
   ```

2. **Сложные составные условия**
   ```go
   // ❌ Сложно читать
   switch {
   case (a > 0 && b < 10) || (c == 5 && d != 0):
       ...
   }
   
   // ✅ Лучше if с именованной переменной
   condition := (a > 0 && b < 10) || (c == 5 && d != 0)
   if condition {
       ...
   }
   ```

3. **Разные переменные в каждом условии**
   ```go
   // ❌ switch не подходит
   switch {
   case username == "admin":
       ...
   case password == "123":
       ...
   case email.Contains("@"):
       ...
   }
   
   // ✅ Лучше отдельные if
   ```

***

## Сравнительная таблица: switch vs if-else

| Критерий | if-else | switch |
|---|---|---|
| **Синтаксис** | `if x == 1 { } else if x == 2 { }` | `switch x { case 1: case 2: }` |
| **Читаемость** | Средняя (3+ условия) | ✅ Отличная |
| **Компактность** | Многословно | ✅ Компактно |
| **Множественные значения** | `x == 1 \|\| x == 2 \|\| x == 3` | ✅ `case 1, 2, 3:` |
| **Break** | Не нужен | ✅ Автоматический |
| **Типы данных** | Любые | Любые + type switch |
| **Диапазоны** | `x >= 10 && x < 20` | ✅ `case x >= 10 && x < 20:` |
| **Применение** | 1-2 условия | ✅ 3+ условий |
| **Fallthrough** | Нет концепции | Явный `fallthrough` |
| **default** | `else` | `default:` |

***

## Best Practices

### 1. Используйте switch для 3+ проверок

```go
// ❌ Плохо: if для множественных проверок
if x == 1 {
    ...
} else if x == 2 {
    ...
} else if x == 3 {
    ...
} else if x == 4 {
    ...
}

// ✅ Хорошо: switch для множественных проверок
switch x {
case 1: ...
case 2: ...
case 3: ...
case 4: ...
}
```

### 2. Группируйте связанные значения

```go
// ✅ Хорошо: группировка через запятую
switch statusCode {
case 200, 201, 204:
    fmt.Println("Успех")
case 400, 401, 403, 404:
    fmt.Println("Ошибка клиента")
case 500, 502, 503:
    fmt.Println("Ошибка сервера")
}
```

### 3. Используйте default для неожиданных случаев

```go
// ✅ Хорошо: всегда обрабатывайте неожиданные значения
switch role {
case "admin": ...
case "user": ...
default:
    log.Printf("Неизвестная роль: %s", role)
}
```

### 4. Избегайте fallthrough без необходимости

```go
// ❌ Плохо: fallthrough усложняет понимание
switch x {
case 1:
    doSomething()
    fallthrough
case 2:
    doAnotherThing()
}

// ✅ Хорошо: явные действия
switch x {
case 1:
    doSomething()
    doAnotherThing()
case 2:
    doAnotherThing()
}
```

### 5. Switch без выражения для диапазонов

```go
// ✅ Хорошо: switch без выражения для условий
switch {
case age < 18:
    fmt.Println("Несовершеннолетний")
case age < 65:
    fmt.Println("Взрослый")
default:
    fmt.Println("Пенсионер")
}
```

### 6. Комментируйте неочевидные case

```go
switch statusCode {
case 200:
    // Успешный запрос
    processData()
case 429:
    // Rate limit - повторим позже
    scheduleRetry()
case 503:
    // Сервис недоступен - используем кэш
    useCachedData()
}
```

### 7. Упорядочивайте case логично

```go
// ✅ Хорошо: от частых к редким или по приоритету
switch command {
case "start":     // Самая частая
    ...
case "stop":      // Частая
    ...
case "restart":   // Средняя
    ...
case "debug":     // Редкая
    ...
}
```

## Типичные ошибки

### Ошибка 1: Забытый break (в других языках)

```java
// Java - ОШИБКА
switch (x) {
    case 1:
        System.out.println("Один");
        // Забыли break - провалится в case 2!
    case 2:
        System.out.println("Два");
}
```

**В Go эта ошибка невозможна** — break автоматический!

### Ошибка 2: Регистр в строках

```go
// ❌ Не сработает
dayOfWeek := "saturday"  // маленькая буква

switch dayOfWeek {
case "Saturday":  // большая буква
    fmt.Println("Выходной")
}
// Ничего не выполнится!
```

**Решение:** Проверяйте регистр или используйте `strings.ToLower()`.

### Ошибка 3: Использование fallthrough неправильно

```go
// ❌ Плохо: fallthrough в последний case бесполезен
switch x {
case 1:
    fmt.Println("Один")
    fallthrough  // Бесполезно - дальше default
default:
    fmt.Println("Другое")
}
```

***

## Ключевые моменты

1. **switch** — альтернатива каскадам if-else для проверки множественных значений
2. **Автоматический break** — не нужен явный выход из case
3. **Множественные значения** — `case 1, 2, 3:` через запятую
4. **Switch без выражения** — `switch { case условие: }` для диапазонов
5. **fallthrough** — явное проваливание в следующий case
6. **default** — выполняется если ни один case не подошёл
7. **Инициализация** — `switch x := expr; x { }` для локальных переменных
8. **Type switch** — проверка типов через `.(type)`
9. **Читаемость** — switch делает код чище при 3+ проверках
10. **IDE-подсказки** — используйте автоматический рефакторинг if → switch

***

## Что запомнить

- **switch выражение { case значение: }** — базовый синтаксис
- **break не нужен** — автоматический выход
- **case 1, 2, 3:** — множественные значения через запятую
- **switch { case условие: }** — switch без выражения
- **fallthrough** — явный переход к следующему case
- **default:** — блок по умолчанию
- **3+ проверки** — используйте switch, не if
- **Регистр важен** — "Saturday" ≠ "saturday"
- **Компактнее и читаемее** — главное преимущество
- **Type switch** — для проверки типов переменных

***

**Итог:** Оператор switch в Go — мощная и элегантная альтернатива каскадам if-else для проверки множественных значений. Автоматический break делает код безопаснее, возможность множественных значений в case через запятую делает его компактнее, а switch без выражения позволяет проверять диапазоны так же удобно, как if-else, но с лучшей структурой. Используйте switch когда проверяете 3+ значения одной переменной — код станет чище, короче и читаемее. IDE подскажет, когда if-else можно заменить на switch — не игнорируйте эти подсказки.
